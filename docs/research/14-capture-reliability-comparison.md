# Capture reliability: two local dictation implementations and library guidance

Research only; no change to the capture design. Source snapshot: local nvstt revision `7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f`. GitHub returned 404 for this revision, so the nvstt GitHub line links below are local-source pointers only. Read the cited paths in this checkout. Upstream links are pinned separately. The upstream repositories below were checked out at the full commits in their links. The library documentation is for the versions in nvstt's `Cargo.toml`: CPAL 0.18.1, rtrb 0.4.0, and rubato 5.0.0. These are source/design comparisons, not measured performance results. I inspected the named nvstt sources, the capture and VAD source they call, and upstream implementations; I did not run live-device or native-VAD measurements.

## Two verified open-source comparisons

| [whisper.cpp `whisper-stream`](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L1-L4) | An SDL input callback copies floating-point samples into a fixed-duration circular buffer. It limits an oversized callback to the newest samples and caps the retained length at buffer capacity ([SDL capture source](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/common-sdl.cpp#L35-L76), [write path](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/common-sdl.cpp#L138-L167)). The default step is 3 s, window 10 s, and overlap 200 ms ([defaults](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L17-L29)). | This is a rolling **window**, not a loss-accounting, once-only capture queue. In non-VAD mode it warns, clears, and continues if more than two steps of new audio have arrived ([loop](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L251-L291)); the circular buffer can already have overwritten older samples. The repeated overlap mitigates *decoding-window* word splits, but repeats audio deliberately ([overlap update](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L408-L412)). Do not copy its overwrite/clear policy into final-only dictation. This continuously running example does not test nvstt's hotkey stop contract. |
| [nerd-dictation](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1-L7) | Starts `parec`, `sox`, or `pw-cat` with mono raw PCM on subprocess stdout; makes that pipe nonblocking, starts recording before loading Vosk, then reads available bytes into `AcceptWaveform` ([process setup](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L867-L925), [startup](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L945-L983), [read loop](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1186-L1233)). It skips idle time if processing is behind ([loop pacing](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1203-L1216)). | A separate capture process moves buffering outside this code's callback. The reviewed read path does not count lost input frames or establish a capture-time-to-read-time bound; it cannot establish that every frame reaches Vosk. The end request changes a cookie, checked at the **top** of each loop; the code then signals the recording process and calls `FinalResult`, without an explicit post-stop drain of remaining pipe bytes ([end request](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1469-L1479), [loop/end](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1192-L1194), [finalization](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1245-L1265)). This is a *risk to test*, not proof that a particular word was lost. Its optional `--delay-exit` **continues recording after end**, if text was handled; that changes the end boundary rather than draining already captured audio ([exit logic](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1345-L1363), [option](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1666-L1675)). |

**VAD is not one interchangeable fix.** `whisper-stream` switches to a 2-second polling/window path only when `step <= 0`; it tests the recent 2 seconds with `vad_simple` and then transcribes the larger retained window ([mode](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L129-L142), [loop](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/stream/stream.cpp#L292-L313)). That function optionally high-pass filters and compares recent versus whole-window mean absolute energy; it is not nvstt's Silero gate ([implementation](https://github.com/ggml-org/whisper.cpp/blob/a44e07845931421bb6f3447ce0010ed9dc76a118/examples/common.cpp#L610-L646)). nerd-dictation uses Vosk `AcceptWaveform` and partial/final results; its `--timeout` watches for unchanged recognition JSON, not independently measured acoustic silence ([read/timeout path](https://github.com/ideasman42/nerd-dictation/blob/41f372789c640e01bb6650339a78312661530843/nerd-dictation#L1227-L1243)). Neither path shows that a different VAD threshold improves nvstt word boundaries.

## Official guidance and the current nvstt design

- **Callback and start:** CPAL says `play()` starts periodic data callbacks on a dedicated high-priority thread on modern platforms. Some blocking backends use a CPAL-managed thread instead ([CPAL 0.18.1 crate guide](https://docs.rs/cpal/0.18.1/cpal/#how-to-use-cpal)); build accepts distinct data and error callbacks ([`DeviceTrait`](https://docs.rs/cpal/0.18.1/cpal/traits/trait.DeviceTrait.html#method.build_input_stream)). nvstt selects the default supported input format, builds and plays the stream, and downmixes/pushes inside the callback; VAD, resampling, and inference run on the worker ([recorder build/start](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L244-L330), [writer](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L133-L154), [worker](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L120-L157)). CPAL does not promise that returning from `play()` means the first microphone frame has arrived. nvstt sends `listening` after stream/worker startup; it does not record the first callback time ([app startup](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L348-L427)). This is a boundary to **measure**, not an established cause of missing first words.
- **Queue overflow:** rtrb specifies fixed capacity, single producer/consumer, immediate nonblocking `push`/`pop`, and **no overwrite** on full; it provides no built-in wait for a full or empty buffer ([rtrb 0.4.0 crate guide](https://docs.rs/rtrb/0.4.0/rtrb/)). Its readable `Consumer::slots()` can increase during a drain ([consumer API](https://docs.rs/rtrb/0.4.0/rtrb/struct.Consumer.html#method.slots)). nvstt uses one owned consumer, a five-second *mono-sample* queue at the input device's rate, counts failed pushes, and snapshots available slots for each drain ([queue/source](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L157-L221), [capacity](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L292-L297)). A full queue fails the capture rather than silently producing a partial transcript ([integrity](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L85-L121)). Five seconds is capacity, **not** a bound on upstream/backend loss, callback lag, recognition latency, or permitted session duration.
- **Stop and final tail:** nvstt drops the stream before checking capture integrity, then sends Finish to the worker. The worker checks integrity, drains the remaining queue, flushes the pipeline, checks integrity again, and only then finalizes recognition ([recorder stop](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L333-L343), [stop ordering](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L431-L455), [worker finish](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L175-L233)). Failure prevents history and delivery ([app failure path](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L566-L584), [capture-fault tests](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L1028-L1055)). This protects against **known** queue/backend failures and loss of **already queued** tail audio. It does not show which phonemes the device captured before `play()` or after hotkey release. ADR 0013 explicitly keeps this integrity policy and says unit tests do not establish WER, native VAD, or stop-to-insertion latency ([decision](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/docs/adr/0013-dictation-integrity.md#L7-L17), [limitations](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/docs/adr/0013-dictation-integrity.md#L47-L50)).
- **Timestamp verification:** CPAL exposes `InputCallbackInfo::timestamp()` with `callback` and `capture` instants ([info](https://docs.rs/cpal/0.18.1/cpal/struct.InputCallbackInfo.html#method.timestamp), [timestamp fields](https://docs.rs/cpal/0.18.1/cpal/struct.InputStreamTimestamp.html)). `StreamInstant` values support elapsed-time comparisons **within one stream**; different streams need not share an origin ([clock warning](https://docs.rs/cpal/0.18.1/cpal/struct.StreamInstant.html)). nvstt ignores the callback info today ([callback](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L254-L263)). Measure `callback - capture` where the backend provides valid timestamps. Measure hotkey-to-callback or callback-to-text separately using one comparable process clock, or calibrated external markers. Do **not** subtract a CPAL stream instant directly from `std::time::Instant` or compare origins from two streams.
- **Resampler tail:** Rubato recommends `process_into_buffer` with preallocated buffers for time-sensitive use; `process()` allocates. It explains chunk sizes, `input_frames_next()`/`output_frames_next()`, startup delay, and missing tail if one fails to flush/trim a clip ([real-time considerations](https://docs.rs/rubato/5.0.0/rubato/#real-time-considerations), [chunk sizes](https://docs.rs/rubato/5.0.0/rubato/#input-and-output-sizes-per-call), [`Resampler` methods](https://docs.rs/rubato/5.0.0/rubato/trait.Resampler.html#tymethod.process_into_buffer), [`Indexing.partial_len`](https://docs.rs/rubato/5.0.0/rubato/struct.Indexing.html#structfield.partial_len)). nvstt already runs its fixed-ratio FFT resampler off the callback; it preallocates input/output buffers, tracks `output_delay()`, supplies a partial final chunk, drains the delayed tail, and trims to the expected output length ([audio pipeline](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/audio_pipeline.rs#L138-L250)). Do not move resampling into the CPAL callback merely to reduce observed queue size. Keep resampler correctness tests separate from microphone-capture claims.
- **VAD boundaries:** nvstt's Silero gate uses 512-sample/16 kHz frames, 400 ms pre-roll, a 200 ms bridge on renewed speech, and a 30-second **detector segment** setting; its 30-minute **capture-session** limit is distinct ([gate settings](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/speech_gate.rs#L15-L19), [routing](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/speech_gate.rs#L36-L76), [detector](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/speech_gate.rs#L149-L172), [capture limit](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L11-L12)). It keeps the first non-speech boundary frame after active speech and flushes a partial detector frame at finish ([gate finish](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/speech_gate.rs#L59-L65), [flush](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/speech_gate.rs#L108-L115)). These protect some *detector* boundaries, not frames never delivered by the device. ADR 0013 says to keep the detector settings and one ASR stream per dictation ([decision](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/docs/adr/0013-dictation-integrity.md#L13-L17)).

## Measurable next steps, not inferred fixes

1. **Measure start and end delivery.** In a controlled loopback or hardware capture run, place known speech-like markers at fixed offsets around both hotkey edges. Save a *temporary, consented* input-side trace and callback timestamps. Report first-callback delay, last captured marker, callback capture-to-delivery lag, and boundary marker omission rate per device/backend. Use the same clock for compared events; compare CPAL timestamps only within their stream. Run with the speech gate both on and off to distinguish capture from detector routing. A live microphone test is necessary; file-only WER cannot settle either boundary.
2. **Measure queue headroom with paced input.** At native sample rates and several callback sizes, replay 20 ms paced chunks for short and long sessions. Record high-water `slots`, time spent near capacity, failed-push samples, worker service time, stop-to-worker-drain time, and error/delivery outcome. Add deterministic pause/stall injection and assert exact retained order, count, and failure with no delivered partial text. Separate queue loss from backend errors and duration-limit rejection. Compare p50/p95/p99 and worst observed values; **do not** choose a new capacity before collecting a workload distribution. nvstt currently tests concurrent order, full-queue loss, an entry snapshot, and a stop/callback race, but not native hardware timing ([recorder tests](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L412-L421), [concurrent snapshot tests](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L499-L560), [snapshot test](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/recorder.rs#L586-L593), [app race test](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/app.rs#L1058-L1185)).
3. **Score transcript and wall-clock effects separately.** Reuse nvstt's private, external-audio manifest to stratify first-word, last-word, long-pause, quiet-speech, and silence/noise clips; report deletions/insertions, WER, and silent-clip failures. Its 20 ms **file replay** measures a *virtual* backlog plus model finalization, not callback timing, queue pressure, or actual hotkey-to-insertion latency ([evaluation setup](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/evaluation.rs#L1-L51), [scoring](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/evaluation.rs#L130-L182), [simulation](https://github.com/shubham-cpp/nvstt/blob/7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f/src/evaluation.rs#L193-L232)). Measure real release-to-result and release-to-insertion independently. Pair each boundary failure with its capture trace before assigning cause to CPAL, queueing, resampling, VAD, ASR, or delivery.

**Non-goals:** Do not silently overwrite or clear capture on overflow, treat a VAD swap as a capture fix, assume a five-second queue is a five-second latency guarantee, or add post-release recording without changing the hotkey contract. Do not change the 400 ms pre-roll, 200 ms bridge, 30-second detector setting, or one-ASR-stream decision on this evidence alone. Do not store raw microphone audio in Git or history. No observed boundary failure or causal attribution is claimed by this report.
