## What the native online API does

1. Feed normalized waveform, then call `is_ready` before each `decode`; `get_result` returns a **current hypothesis snapshot**, not an instruction to finish or an automatic decode operation. The Rust `get_result` returns `None` if its C JSON pointer is null **or JSON parsing fails**. nvstt currently replaces `None` with empty text, so such a failure is indistinguishable from an empty hypothesis. See [C API lines 536-595, 613-641](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/c-api/c-api.h#L536-L641), [Rust lines 386-436](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/rust/sherpa-onnx/src/online_asr.rs#L386-L436), `src/recognizer.rs:174-189,217-233`.
2. Call `input_finished()` **after the last waveform**. It forwards to the feature extractor. The C API says not to append samples afterward. It does not promise to add enough waveform for every transducer chunk. Loop on `is_ready` again, then read the result; nvstt follows this order. See [C API lines 705-717](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/c-api/c-api.h#L705-L717), [Rust lines 465-479](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/rust/sherpa-onnx/src/online_asr.rs#L465-L479), [stream lines 24-41](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-stream.cc#L24-L41), `src/recognizer.rs:217-233`.
3. **Model-specific distinction.** Sherpa-onnx selects Parakeet Unified using decoder metadata. Its `IsReady` has an EOF path for a short final chunk; `CopyWindowWithPadding` zero-pads *features*, then decoding consumes only valid center frames. For other NeMo transducers (the Nemotron path), `IsReady` remains `processed + ChunkSize() < NumFramesReady()`; it has no corresponding `IsLastFrame` branch. `ChunkSize` comes from encoder metadata `window_size`. End-of-input can make final acoustic features available, but it does **not** waive this full-chunk readiness check. See [dispatch lines 54-59,108-130](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-recognizer-impl.cc#L54-L130), [Parakeet lines 77-90,182-210,233-280](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-recognizer-transducer-nemo-parakeet-unified-impl.h#L77-L90), [NeMo lines 80-90,158-194](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-recognizer-transducer-nemo-impl.h#L80-L90), [encoder metadata lines 314-316,489-491](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-transducer-nemo-model.cc#L483-L491). Check the downloaded decoder metadata to confirm selection for any changed artifact. The general transducer implementation also uses the strict chunk test: [lines 248-250](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-recognizer-transducer-impl.h#L248-L250).
4. `enable_endpoint = true` enables a **separate query**: `is_endpoint`. Default rules check 2.4 s trailing blanks without tokens, 1.2 s with tokens, or 20 s duration. It does not call `reset` or finalize by itself. nvstt never calls `is_endpoint` or `reset` on its dictation stream; it keeps one stream until release, then discards it. A silence boundary in the VAD is not a sherpa-onnx ASR endpoint. See [endpoint defaults lines 39-52](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/endpoint.h#L39-L52), [NeMo endpoint lines 110-146](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/online-recognizer-transducer-nemo-impl.h#L110-L146), [Rust `is_endpoint`/`reset` lines 403-417](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/rust/sherpa-onnx/src/online_asr.rs#L403-L417), `src/recognizer.rs:155-170,191-239`. Do not treat `is_ready == false` as an endpoint or proof that all captured words were decoded.

## Silero VAD: turn-on, turn-off, and flush

- The configured 16 kHz, 512-sample (32 ms) windows, 0.5 threshold, 250 ms minimum speech, and 500 ms minimum silence are in `src/speech_gate.rs:14-19,149-167`. Silero requires sustained above-threshold speech before `triggered_` becomes true; after speech, below-threshold windows remain speech until the silence timer expires. The effective boundary is quantized by frames and depends on measured probabilities, not a guaranteed exact 250/500 ms. See [Silero `IsSpeech` lines 98-171](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/silero-vad-model.cc#L98-L171).
- `detected()` indicates **an active segment** (`start_ != -1`), while `front()` holds a **completed** segment. After a speech-to-silence transition, sherpa-onnx queues a segment trimmed by its minimum silence duration. `flush()` instead queues the current buffered segment up to the current buffer tail **only if it is already active**. It does not run a pending, too-short audio window through the model, create speech from an undetected short utterance, or pad the ASR stream. See [VAD lines 67-135,170-196](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/voice-activity-detector.cc#L67-L196), [Rust methods lines 216-280](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/rust/sherpa-onnx/src/vad.rs#L216-L280).
- The native VAD's `buffer_size_in_seconds` is a **circular-buffer capacity**, not an automatic 30-second speech cutoff. When its buffered audio passes `max_speech_duration`, the detector changes to 0.1 s minimum silence and 0.90 threshold to encourage a boundary. Thus nvstt's 30 s settings do not impose a hard 30 s dictation limit. See [VAD lines 27-32,50-65,202-209](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/voice-activity-detector.cc#L27-L65), `src/speech_gate.rs:17-19,155-167`.

## nvstt contrast and risk classification

- **Confirmed routing behavior:** `GateState` sends up to 400 ms of retained pre-roll when speech first turns on. It sends each active frame and the first `detected == false` frame. It stops sending further silence. On a later turn-on it adds 200 ms of zero samples and retained pre-roll. See `src/speech_gate.rs:14-17,37-77`. This preserves a VAD transition frame, but the inactive frames after that are *not* sent to ASR.
- **Confirmed flush behavior:** nvstt zero-pads only a partial **VAD** 512-sample frame (at most 511 samples / 31.94 ms), feeds it through the gate, then calls native VAD `flush()`. It copies queued native segment samples only when `saw_speech` is false; otherwise it discards queued segments because its own frame routing already supplied speech. `VadGatedRecognizer` cancels the ASR stream and reports `NoSpeech` when the gate saw no speech. See `src/speech_gate.rs:108-115,193-243`, `src/recognizer.rs:287-304`. Native VAD flush is **not** the same as online ASR `input_finished()`.
- **Confirmed audio stop path:** `AudioPipeline::finish` drains resampler/denoiser tails but inserts no intentional ASR silence. Evaluation uses 20 ms feeds, calls that pipeline finish, then finishes the recognizer. See `src/audio_pipeline.rs:53-82,179-207`, `src/evaluation.rs:193-256`. Config defaults to Nemotron 560 ms with gate enabled; Parakeet remains selectable and normally defaults to gate off for a legacy config. See `src/config.rs:11-15,66-115,142-172,205-210,226-245`.
- **Supported risk, not a measured bug:** When the gated or ungated Nemotron stream ends with insufficient ready features for another full chunk, `input_finished()` plus `while is_ready` can leave a final sub-chunk undecoded. Releasing during a word, short utterances, and removing post-speech silence raise this risk. Neither the API nor these sources prove *which* user word is lost in a given clip. The Parakeet Unified final-chunk implementation lowers this particular risk; it does not prove identical transcript quality. Short speech rejected by VAD is a distinct risk: its `flush` cannot make an inactive segment speech. A zero-padded partial VAD frame may also change a borderline decision. Tests must establish frequency and severity with the actual artifacts.
- **Separate check:** A null or unparsable `get_result` becomes `Transcript("")` (`src/recognizer.rs:227-233`). This loss of failure information is proven in code, but no native result failure was observed here. Do not label it the cause of a missing last word without instrumentation.

## End-of-stream padding: recommendation, not a fixed contract

Sherpa-onnx's tagged **general** online WAV example sends 0.3 s zeros before audio and 0.8 s zeros after audio, *then* calls `InputFinished` and drains `IsReady`: [example lines 130-151](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/sherpa-onnx.cc#L130-L151). Its VAD-to-online-ASR example sends **1.28 s zeros**, noting that the amount relates to the model chunk size, before `InputFinished`: [example lines 144-145,173-186](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.4/sherpa-onnx/csrc/sherpa-onnx-vad-with-online-asr.cc#L144-L186). These are example choices, **not** a universal 0.8 s or 1.28 s requirement for Nemotron or Parakeet Unified. For the strict NeMo chunk condition, enough *additional waveform* to cross the next readiness threshold can expose residual speech to decoding. EOS can make an incomplete feature frame available but cannot by itself ensure a full ASR chunk. No artificial silence is needed **when sufficient real waveform has already made the relevant chunk ready**; for an arbitrary short final chunk it may be needed with Nemotron's tagged implementation. Parakeet Unified explicitly zero-pads its final *feature window* on EOS. Do not add zeros to VAD input as a substitute for ASR-only padding without testing: VAD may reject, trim, or stop routing them. Pad only **before** `input_finished()` if a test shows a need. Do not infer a correct pad length from a model card's nominal 560 ms latency; measure the actual ONNX `window_size` and `chunk_shift`, feature frames, and boundary outcome.

NVIDIA calls [Nemotron cache-aware with 80/160/560/1120 ms chunk options](https://huggingface.co/nvidia/nemotron-speech-streaming-en-0.6b/blob/ebe59e5a817142986528bbbee5dba8db7b38ed50/README.md#L188-L190); its [80 ms frame and right-context table](https://huggingface.co/nvidia/nemotron-speech-streaming-en-0.6b/blob/ebe59e5a817142986528bbbee5dba8db7b38ed50/README.md#L347-L356) does not specify sherpa-onnx EOS. NVIDIA calls [Parakeet Unified's streaming inference buffered](https://huggingface.co/nvidia/parakeet-unified-en-0.6b/blob/fe53cd885760c96b6a5f51a0bfd362cb4584a98b/README.md#L252-L261); its [latency table](https://huggingface.co/nvidia/parakeet-unified-en-0.6b/blob/fe53cd885760c96b6a5f51a0bfd362cb4584a98b/README.md#L358-L370) defines latency as chunk plus right context, not required end padding. Neither card promises that silence is mandatory for recognition or that an `input_finished()` call alone decodes every chunk in every runtime.

## Discriminating tests (proposed, not run)

1. **Native ASR only, each installed model/profile:** Feed the same reference WAV in 20 ms chunks. Compare stop at exact speech end, +100/300/600/800/1280 ms added *ASR-only* zeros, and recorded natural trailing silence. Run `input_finished`, drain, capture text, tokens, `is_ready` transitions, time and repeated-run variance. Sweep stop offsets across the chunk period and include utterances shorter than one chunk. Compare end-word deletion and insertion, not just nonempty text. Log ONNX metadata `window_size`/`chunk_shift`. A transcript that recovers only after padding supports the final-chunk hypothesis; no change weakens it.
2. **Gate isolation:** Replay speech followed by 0, 0.2, 0.5, 1.0, and 2.0 s silence with gate on/off. Log detector `detected`, queue events, routed sample counts, `saw_speech`, final gate output, and ASR result. Compare ASR-only silence after gate finish with silence sent *through* the gate. This separates VAD withholding silence from ASR readiness and from acoustic ambiguity.
3. **VAD boundaries:** Feed clips around the 250 ms minimum speech, around the 500 ms stop, and at VAD frame offsets 0, 1, and 511 samples. Include noise, repeated speech regions, and an utterance longer than 30 s. Compare native VAD completed segments and flush, gate frames, and expected `NoSpeech`. Tests for the pure `GateState` and `GateInput` in `src/speech_gate.rs:254-376` do not exercise native Silero probabilities or the ASR.
4. **Integration and acceptance:** Use the private evaluation manifest on both models, gate on/off, and CPU/CUDA where available. Record WER, last-word deletions, silent-clip failures, and warmed stop-to-result p50/p95 separately. `src/evaluation.rs:193-233` measures model finalization plus simulated worker backlog, **not** actual desktop text insertion. Repeat with paced capture and real insertion timing before claiming a user-visible fix. Treat a nonempty/empty result or observed latency as evidence only for that model, profile, clip, and runtime.

**Conclusion:** nvstt calls the online API in the correct order. Its VAD flush cannot replace ASR tail padding. Sherpa-onnx `v1.13.4` can leave a short final Nemotron chunk unready after EOS; Parakeet Unified has a dedicated EOS short-chunk path. Whether this causes any nvstt transcription loss, and what padding is safe and sufficient, require the controlled tests above.
