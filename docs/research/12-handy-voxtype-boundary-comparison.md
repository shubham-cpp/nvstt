# Handy and voxtype: dictation boundary comparison

**Scope and evidence.** This is source research, not a measurement or a diagnosis of word loss in nvstt. “Observed” means the cited code or first-party documentation says or does this. “Inference” means a possible effect that needs a test. The compared repositories are [Handy](https://github.com/cjpais/Handy) at [`8f9cf53cd1410cda26beea39ff802ac306e39585`](https://github.com/cjpais/Handy/tree/8f9cf53cd1410cda26beea39ff802ac306e39585) and [voxtype](https://github.com/peteonrails/voxtype) at [`320a737e5d3c8662e0ec7de95f75407baa784d82`](https://github.com/peteonrails/voxtype/tree/320a737e5d3c8662e0ec7de95f75407baa784d82). [Handy's official site](https://handy.computer) links to `cjpais/Handy`; [voxtype's official site](https://voxtype.io) links to `peteonrails/voxtype`. Their first-party [Handy README](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/README.md#L18-L32) and [voxtype README](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/README.md#L1-L8) describe shortcut-driven dictation. Source links below are pinned to these commits. nvstt references use the local checkout at `7ca8ccb27a00b3ad2ffec3f0b03057ac0560f14f` and relative file/line links; this commit was not found through the public GitHub commit API.

## Boundary comparison

| Boundary | Handy — observed | voxtype — observed | Relevance to nvstt — inference |
| --- | --- | --- | --- |
| Mic start | The manager can keep a stream open or open it on demand. It calls `start()` after selecting the VAD profile; the recorder queues `Start` and acknowledges **the first captured chunk**, not merely `stream.play()` ([manager](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/audio.rs#L816-L851), [recorder](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L374-L391), [UI cue](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/actions.rs#L543-L584)). Idle audio is discarded; `Start` can include audio already in flight in the ring ([consumer](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L916-L958)). | Each `start()` builds and plays a CPAL input stream in a capture thread. It returns a 64-chunk receiver after spawning the thread, **without waiting for the first callback** ([capture](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/audio/cpal_capture.rs#L154-L188), [thread/return](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/audio/cpal_capture.rs#L263-L345)). | A first-sample readiness marker could separate device-start delay from VAD or ASR errors. It cannot recover words spoken **before** actual capture. |
| Capture queue | CPAL writes to a two-second, single-producer/single-consumer ring; a separate consumer drains bounded chunks and processes VAD. Overflow is counted and logged but recording continues ([ring](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L30-L47), [write/overrun](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L426-L547), [warning](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L857-L870)). Live ASR frames use a separate, **unbounded** FIFO command channel; `Feed` precedes `Finalize` on that channel ([router](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/transcription.rs#L98-L182)). | The callback stores the resampled audio in a shared `Vec` for batch transcription, then attempts `try_send` to a 64-chunk channel; failure to send a live chunk is ignored ([capture](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/audio/cpal_capture.rs#L420-L466)). The streaming tap has another bounded 64-chunk channel and also drops on `try_send` failure ([daemon](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L1665-L1717)). | Do **not** replace nvstt's integrity check with either project's permissive loss policy. Queue capacity is not proof that no chunks were lost. |
| VAD and first word | An active VAD gates each frame. The wrapper requires 60 ms of onset, replays a bounded prefill on detection, then keeps 450 ms of offline or 1,650 ms of streaming hangover. Frame counts round up for detector frame size ([profile](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/vad/mod.rs#L1-L15), [construction](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/audio.rs#L280-L326), [routing](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/vad/smoothed.rs#L55-L119)). The nominal prefill is 450 ms. | Batch VAD is **whole-recording accept/reject**, not segment cropping: it checks the collected samples, then transcribes those same samples if speech is detected ([daemon](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L2473-L2547), [energy detector](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/vad/energy.rs#L65-L127)). Its Whisper VAD sets segment parameters with an upstream library's default 30 ms padding, but this code uses the result only to decide whether to transcribe the **uncropped** recording ([Whisper detector](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/vad/whisper_vad.rs#L52-L106)). [First-party VAD docs](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/docs/CONFIGURATION.md#L3028-L3067) say VAD rejects silent recordings; it is off by default. | Whole-clip VAD preserves weak boundary audio that a gate might omit, but sends more silence and noise to ASR. Do not call the library's segment padding a voxtype mic pre-roll. |
| Mic stop and last word | `Stop` requests a callback pause, forwards one boundary block, waits up to two seconds for acknowledgment, drains the ring as capture, then flushes the resampler and final partial VAD frame ([consumer](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L956-L1004), [resampler](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/resampler.rs#L68-L119)). A user setting can extend **actual capture** past release; its default is zero ([manager](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/audio.rs#L983-L1015), [default](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/settings.rs#L961-L971)). Zero padding of short finished audio is separate from this setting ([manager](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/audio.rs#L1043-L1057)). **No VAD tail replay at stop**: the tail report is diagnostic only ([recorder](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/audio/recorder.rs#L872-L909), [VAD](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/vad/mod.rs#L44-L73)). | Batch stop drops the stream, flushes delayed resampler output into the collected `Vec`, returns a clone, then transcribes it ([capture](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/audio/cpal_capture.rs#L278-L324), [resampler](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/audio/resampler.rs#L108-L151), [daemon](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L2458-L2539)). **Live mode differs**: stop first aborts the forwarding pump, then stops capture, so audio still buffered for batch capture or flushed from its resampler is not guaranteed to reach the streaming backend. The code's stated reason is to avoid post-stop noise and hallucinated tokens ([cut](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L1486-L1490), [stop](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L1504-L1512)). | Flush delayed *captured* audio before ASR finalization. Adding post-release capture could help if release precedes the last phoneme, but delays completion and can add noise. Do not equate resampler flush, VAD hangover, and recording for more time. |
| Inference completion and text | Live `Feed` and `Finalize` share a FIFO; finalization calls the engine's `stream.finalize()` and reads its final text. If no usable live text remains, the caller batch-transcribes the saved audio; a finalize **timeout** is reported instead of starting a competing fallback ([worker](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/transcription.rs#L991-L1063), [reply](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/transcription.rs#L1107-L1148), [caller](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/actions.rs#L704-L733)). Final text then gets optional word correction, language-aware filler removal, and stutter/space normalization; panics in optional cleanup fall back to raw text ([pipeline](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/managers/transcription.rs#L1769-L1845), [cleanup](https://github.com/cjpais/Handy/blob/8f9cf53cd1410cda26beea39ff802ac306e39585/src-tauri/src/audio_toolkit/text.rs#L327-L437)). | Batch awaits capture then starts background transcription. Live Parakeet flushes its own recognizer at receiver EOF; sliding-window mode makes a final transcription pass with best-effort tail reconciliation ([batch](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L2444-L2557), [Parakeet](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/transcribe/parakeet_streaming.rs#L238-L280), [sliding window](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/transcribe/sliding_window.rs#L679-L735)). For live **file** output, it folds a pending partial into final text; for live **cursor** output, it disowns the typing session on stop to avoid typing after focus changes ([file](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L1361-L1395), [fold](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L1535-L1565)). Batch text cleanup can delete filler words, replace phrases, convert spoken punctuation, and remove a trailing “submit” command ([processor](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/text/mod.rs#L149-L208), [application](https://github.com/peteonrails/voxtype/blob/320a737e5d3c8662e0ec7de95f75407baa784d82/src/daemon.rs#L2563-L2601)). | A missing *text* suffix need not be a missing *audio* suffix. Compare raw final ASR text with delivered text; keep live partials distinct from final output. |

## What nvstt already does; what to verify

- **Observed:** nvstt starts one ASR session before starting capture; it stops the CPAL stream **before** waiting for the recognition worker. The worker drains its five-second ring, finishes the audio pipeline, checks integrity, then calls recognizer completion. Reported backend failure, duration overflow, or known queue loss blocks delivery ([start/stop](../../src/app.rs#L348-L453), [worker finish](../../src/app.rs#L176-L240), [capture/integrity](../../src/recorder.rs#L83-L155), [limits](../../src/recorder.rs#L1-L14), [decision](../adr/0013-dictation-integrity.md#L9-L18)). This is a stronger known-loss policy than either comparison project.
- **Observed:** its Silero gate uses 512-sample frames, 400 ms pre-roll, and a 200 ms bridge; it retains the frame where detected speech ends and zero-pads a partial frame on finish. It does not simply decode all captured audio ([gate](../../src/speech_gate.rs#L1-L116), [settings/finish](../../src/speech_gate.rs#L142-L220)). Its online recognizer signals `input_finished()` and decodes ready frames before reading the result ([recognizer](../../src/recognizer.rs#L217-L245), [gate wrapper](../../src/recognizer.rs#L287-L308)). Final text cleanup runs after inference ([app](../../src/app.rs#L443-L455), [cleanup](../../src/dictation_transcript.rs#L128-L160)). [ADR 0013](../adr/0013-dictation-integrity.md#L14-L18) keeps the current pre-roll, bridge, detector, and single-stream policy.
- **Inference / test first:** align the actual first callback, stop request, last callback, worker drain, gate output, final ASR text, and cleaned text on the **same** utterance. Use an early first phoneme, an immediate release during the last phoneme, silence after the last word, a pause inside the phrase, and quiet final speech. Compare VAD on/off and denoise on/off. Save and inspect input audio and gate-emitted audio separately. A transcript alone cannot identify which boundary removed a word.
- **Inference / possible changes only after evidence:** if opening the mic late loses the first phoneme, measure start-to-first-sample latency before considering an always-on stream or a readiness cue. If the gate withholds the last phoneme, test a narrowly scoped gate-tail strategy against noise, duplicates, and `NoSpeech`; compare whole-clip VAD as an alternative, not as a guaranteed fix. If samples exist in capture but not at inference, inspect pipeline/gate flush and integrity. If raw ASR has the word but delivery does not, inspect text cleanup. Retain nvstt's failure on **known** loss. Measure stop-to-insertion latency and false additions for any extra real capture after stop.

**Limitations.** These are static observations at two commits, not proof of recognition accuracy, a universal configuration, or a cause in nvstt. Handy can continue after ring overrun; voxtype can drop live chunks even when its batch buffer remains intact. Both can therefore produce a partial live result without proving why a particular word went missing. The source comments describe intended timing, not measured timing on this machine. No audio, microphone, hardware, native-VAD, or word-error tests were run for this report. The Handy clone had unrelated local modifications; only unchanged paths cited at its recorded commit were read. voxtype was cloned separately under `/tmp/nvstt-voxtype-research-20260923`.
